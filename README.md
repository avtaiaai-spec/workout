# Мои тренировки

Личное приложение для тренировок и замеров тела. React + TypeScript + Vite, IndexedDB и офлайн-PWA. Без обязательной регистрации и внешнего сервера данных.

## Запуск

Нужен Node.js 22+.

```sh
npm ci
npm run dev
```

Проверка собранного приложения и PWA:

```sh
npm run build
npm run preview
```

Service worker включён в production-сборке. В разработке Vite он не регистрируется. Для PWA нужен HTTPS или localhost.

## Навигация и сценарии

Три основных раздела на телефоне и компьютере:

- **План** — стартовый экран: выбор недели и даты, все занятия дня, календарь планирования и сохранённые тренировки. Состав раскрывается в строке. Можно начать любой шаблон без расписания, изменить, дублировать, назначить дату/дни недели и архивировать его. Перенос одной даты не меняет серию.
- **Журнал** — список и календарь одних фактических завершённых занятий. Из занятия доступны все подходы, исправление результатов, связь с исходным планом и повторение.
- **Прогресс** — сначала выбор упражнения: последние результаты, отдельные показатели рабочего веса и повторений, применимый внешний объём, время/дистанция, рекорды и полная история. Ниже — регулярность и общие показатели.

Создание тренировки: **выбрать упражнения → настроить подходы → название и сохранение**. Черновик сохраняется в IndexedDB. Можно возвращаться между шагами и добавлять упражнения без потери уже внесённых значений. Каталог доступен в процессе выбора и через «Все упражнения» в «Плане»; поиск, недавние, избранные, категории и оборудование работают вместе. Просмотр техники не сбрасывает выбор.

Строки упражнений в редакторе раскрываются по нажатию. Основная форма задаёт вес, число подходов, повторения и отдых на всё упражнение; раскрываемые индивидуальные настройки позволяют менять отдельные подходы, разминку, комментарии и диапазон плановых повторений. При фактическом выполнении повторения всегда записываются точным числом. Планка использует секунды, кардио — время/дистанцию. Для отведения ноги поддерживаются отдельные подходы на левую и правую стороны.

Активное занятие — отдельный рабочий экран без основной навигации. Сначала показано текущее упражнение и его план; пустых строк всех подходов нет. После фактического выполнения нажмите **«+ Подход»**: появится записанный подход с **заданными вами в плане** весом и повторениями. Запись можно исправить или отменить. Исправление факта не меняет значения следующего подхода. Дополнительные подходы доступны после запланированных. Для отведения ноги каждая сторона записывается отдельно.

Таймер отдыха расположен **внутри упражнения**, запускается после записи при включённом автозапуске, поддерживает +15 с, пропуск и изменение времени. Верхней кнопки и общей панели отдыха нет. Для планки доступен отдельный таймер выполнения подхода. Снизу показана история этого упражнения по всем завершённым занятиям, с фактическими весами, повторениями/секундами, датами и способом учёта. К следующему упражнению переходят отдельной кнопкой; список позволяет свободное переключение и перестановку.

Сворачивание и фон не ставят занятие на паузу: в разделах появляется панель возврата со временем. Перезагрузка восстанавливает выбранное упражнение, значения и таймеры. После записи сохраняется время подтверждения; кнопка и галочка работают с одной записью. При замене частично выполненного упражнения фактическая часть остаётся в занятии, заменяется только оставшаяся работа. Пропуск оставшейся части также сохраняет выполненное.

История служит для сравнения, а кнопка «+» использует установленный план текущего занятия. Плановые значения сохраняются отдельно от фактических исправлений. Снимки занятий независимы от шаблонов. Выполнение назначенного на другой день занятия требует явного действия «Выполнить сейчас»: фактическая дата берётся из текущего времени, исходная связь сохраняется.

«Начать без плана» создаёт пустое фактическое занятие с таймером. После завершения оно записывается в журнал; состав можно дополнительно сохранить новым шаблоном. Повтор из журнала создаёт новый факт с прежними редактируемыми значениями, без старых отметок, дат и длительности. Обновление исходного шаблона после занятия — отдельное добровольное действие.

Три персональные тренировки доступны по кнопке **«Добавить мои три готовые тренировки»** в «Плане». Исходные составы: **7, 5 и 6 упражнений**. Добавление однократное; существующие пользовательские версии не восстанавливаются принудительно к исходным значениям. Плие с гирей и ранее сохранённое плие с гантелью имеют отдельные ID.

## Каталог: только 17 выбранных упражнений

1. Ягодичный мост в рычаговом тренажёре (hip thrust / glute drive).
2. Румынская становая тяга со штангой.
3. Отведение ноги назад в блоке.
4. Разгибание ног сидя в тренажёре.
5. Сведение ног сидя в тренажёре.
6. Приседания плие с гирей.
7. Румынская тяга с гантелями.
8. Гиперэкстензия с акцентом на ягодицы.
9. Сгибание ног лёжа в тренажёре.
10. Разведение ног сидя в тренажёре.
11. Планка на предплечьях.
12. Жим штанги лёжа на горизонтальной скамье в тренажёре Смита.
13. Жим в тренажёре от груди вперёд.
14. Горизонтальная тяга блока сидя узким хватом.
15. Вертикальная тяга широким прямым хватом к груди.
16. Разгибание рук в блоке.
17. Сгибание рук с гантелями.

У всех 17 упражнений новые реалистичные иллюстрации из двух положений, локальные WebP-файлы, описание техники, ошибки, история всех выполненных подходов и прогресс. Изображение можно открыть крупно. Старые изображения из линий и точек удалены. Поиск, категории, оборудование, избранное и выбор нескольких упражнений сохранены. Собственные пользовательские упражнения и изображения сохраняются.

Убраны из видимого встроенного каталога остальные упражнения. При обновлении они сохраняются в `retiredExercises`, а их снимки в тренировках и истории остаются целыми. В старой тренировке упражнение можно заменить вручную. **Плие с гантелью и плие с гирей имеют разные ID и не объединяют результаты.** Для сохранённого старого варианта без новой иллюстрации доступно текстовое описание, а не изображение другого упражнения.

Источники иллюстраций и лицензии: [MEDIA_LICENSES.md](MEDIA_LICENSES.md).

## Замеры тела

Раздел доступен через «Замеры тела» в «Плане» и ссылку в «Прогрессе».

- В сводке и основной форме всегда показаны **вес, грудь, талия и бёдра**. Вес — кг, обхваты — см. Шея, левый/правый бицепс, бедро и голень остаются в дополнительных полях.
- Дата и хотя бы одно положительное значение. Остальные поля необязательны. Ввод принимает точку и запятую.
- История всех записей, изменение и удаление с подтверждением, заметки.
- График выбранного показателя, таблица данных, изменение за период. На графике используется последний замер показателя за день; в истории остаются все записи.
- Период: всё время, 30/90 дней, год или свои даты.
- Отдельный CSV-экспорт и включение всех замеров в полную JSON-копию.

Показатели веса и обхватов не смешиваются с объёмом силовой нагрузки. Автоматические оценки «хорошо/плохо», калории и медицинские рекомендации не рассчитываются.

## Что сохранено

Светлая/тёмная/системная темы Mono Apricot, системный шрифт, компактная адаптивная компоновка, календарь месяца/недели, разовые даты, перенос и отмена одного занятия, будущие изменения недельных серий. Одно активное занятие, пауза, восстановление после перезагрузки, отдельные таймеры подхода и отдыха, ±15 с, произвольное время, звук/вибрация при поддержке браузером. Фактические результаты каждого подхода, комментарии, разминка, пропуск/замена упражнений, порядок, завершение частичного занятия, исправление истории и пересчёт статистики.

Подходы с разными плановыми значениями сохраняются без автоматического выравнивания. В общей форме изменение одного поля меняет только его; индивидуальные отличия доступны в раскрываемом редакторе.

Дробные веса 22,6 / 27,3 / 42,7 / 21,4 кг не округляются до шага тренажёра. В Смите учитывается добавленный вес **без грифа**. Для неуточнённого веса гантелей исходное число сохраняется и исключается из объёма до выбора способа учёта. Отведение ноги поддерживает отдельные отметки левой и правой стороны без повторного удвоения объёма. Планка в разных тренировках ссылается на одно упражнение.

## Хранение, обновление и перенос

Используется прежняя IndexedDB `moi-trenirovki`, объектное хранилище `state`. Формат данных — **версия 3**. Форматы версий 1 и 2 автоматически читаются и мигрируют без удаления тренировок, истории, активного занятия, таймеров, избранного и пользовательских изображений. Версия самой IndexedDB остаётся 1: новые данные находятся в том же объекте состояния, удалять или пересоздавать базу не нужно.

В настройках экспортируйте полную JSON-копию перед переносом или очисткой браузера. Она включает каталог, убранные упражнения, пользовательские изображения data URL, тренировки, расписание, исключения, все занятия, таймеры, настройки, тренировочные дни и замеры тела. Импорт принимает версии 1, 2 и 3, проверяет структуру и дубли ID. Объединение сохраняет текущую запись при совпадении ID; полная замена требует подтверждения. Невалидный файл не меняет текущие данные. CSV-журнал подходов и CSV замеров не заменяют полную копию.

Данные хранятся на конкретном устройстве в конкретном браузере. Синхронизации между устройствами нет. Регулярно сохраняйте копию; браузер может очищать хранилище при нехватке места. Одновременная запись в нескольких вкладках не поддерживается.

Новый service worker активирует свежий кэш сразу, **без принудительной перезагрузки интерфейса**. При открытом приложении появляется «Доступна новая версия»; перед нажатием «Обновить» подтверждается запись текущего состояния в IndexedDB. Если сохранить не удалось, перезагрузка блокируется. В настройках доступны версия сборки и «Проверить обновления». Проверка также выполняется при возвращении в приложение и восстановлении сети. После полной загрузки оболочка и все 17 изображений работают без сети.

Если уже открыта старая версия без кнопки обновления: на компьютере используйте **Ctrl+Shift+R** (macOS: **⌘+Shift+R**). На телефоне закройте все вкладки сайта и отдельное окно установленного приложения, затем откройте сайт снова. **Очистка данных сайта не требуется:** она может удалить локальную историю. Обычная перезагрузка старой версии могла возвращать тот же офлайн-кэш — это исправлено.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
npm run test:updates
```

Проверяются точные шаблоны, неизменность данных, запись по кнопке «+» из плана, исправление факта без изменения будущих подходов, отдельные стороны и секунды, повторение, безопасная замена, статистика и резервные копии.

Браузерные проверки охватывают обе темы на **390×844, 375×667 и 1440×1050**, работу офлайн, четыре показателя тела, историю всех прошлых занятий, отсутствие горизонтальной прокрутки/наложений, контраст, увеличение текста до 200%, клавиатуру, сохранение темы и активного занятия. [Скриншоты](docs/mono-apricot/README.md) используют изолированное тестовое состояние и не добавляются в приложение пользователя.

`test:updates` собирает четыре настоящие версии в отдельном временном каталоге: прежний Calm Studio (`f382211`), Mono Apricot со старым механизмом обновления (`29f827f`), затем две текущие сборки. Он воспроизводит возврат старого интерфейса из кэша, проверяет исправленный переход, уведомление о следующей версии, отсутствие самопроизвольной перезагрузки, сохранение истории/замеров/активного занятия/таймеров, и блокировку обновления при ошибке записи. Нужны указанные Git-коммиты (`git fetch --unshallow` для мелкой копии). CI получает полную историю для этой проверки.

В этой облачной среде есть `/usr/bin/chromium`. На другой машине:

```sh
npx playwright install chromium
CI=1 npm run test:e2e
```

Либо задайте `CHROMIUM_PATH`. Перед браузерными проверками выполните сборку. Скриншоты и trace сохраняются в игнорируемый `test-results/`.

## Публикация и установка на iPhone

В `.github/workflows/pages.yml` настроены проверки и GitHub Pages. После отправки изменений в `main`:

1. В GitHub выберите **Settings → Pages → Source: GitHub Actions**.
2. Дождитесь успешного workflow **Check and publish to GitHub Pages**.
3. Если первая публикация упала до включения Pages, включите его и нажмите **Re-run failed jobs**.
4. GitHub покажет фактический URL в Pages и в deployment workflow.

Для локальной проверки подпапки:

```sh
VITE_BASE_PATH=/workout/ npm run build
VITE_BASE_PATH=/workout/ npm run preview
```

Маршруты используют hash; manifest, изображения и service worker учитывают подпапку. На iPhone откройте опубликованный HTTPS-сайт в Safari → «Поделиться» → «На экран Домой» → «Добавить».

Проверки телефона выполняются в Chromium на мобильном размере экрана. Физический iPhone/Safari не проверялся. Звук при заблокированном экране зависит от браузера и не гарантируется.
