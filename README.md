# Мои тренировки

Личное приложение для зала: планирование, запись подходов и история прогресса. React 19 + TypeScript + Vite, IndexedDB, PWA. Полностью на русском, без регистрации и облачного сервера.

## Запуск

Нужен Node.js 22 или новее (проверено также на Node 24).

```sh
npm ci
npm run dev
```

Vite выведет адрес локального сервера. Для собранного приложения и проверки PWA:

```sh
npm run build
npm run preview
```

Service worker включается в **production-сборке**, а не в `dev`. PWA работает по HTTPS (или на loopback при разработке).

## Что можно делать

- «Сегодня»: продолжить незавершённое занятие, выбрать любую тренировку, посмотреть неделю и ближайшие планы.
- 74 упражнения во всех 12 категориях. Поиск по названиям и синонимам, оборудование, избранное, выбор нескольких упражнений между категориями. Собственные упражнения с необязательным изображением.
- Локальные схемы исходного и конечного положения, пошаговая техника, ошибки, история каждого выполненного подхода и прогресс. Источники и лицензии: [MEDIA_LICENSES.md](MEDIA_LICENSES.md).
- Конструктор: отдельные параметры каждого подхода, отдых, разминка, заметки; копирование параметров всем подходам, добавление, удаление и замена упражнений. Порядок меняется кнопками «Выше / Ниже», а на компьютере ещё перетаскиванием за рукоять.
- Шаблоны редактируются автоматически, дублируются и архивируются. Архив не удаляет историю.
- Расписание: любые дни недели, несколько занятий в день, однократные даты, еженедельные серии с датой начала, отмена и перенос одной даты. Изменение серии действует с выбранной даты, прошлые планы сохраняются.
- Одно активное занятие. Его параметры — отдельный снимок шаблона; обновление страницы сохраняет прогресс. Прошлый соответствующий подход можно скопировать без отметки выполнения. Есть пропуск упражнения, пауза и отмена занятия.
- Независимые таймеры подхода и отдыха с сохранёнными сроками окончания. Отдых: пресеты, своё время, ±15 секунд, остановка и автозапуск. Общая длительность исключает явные паузы и продолжает идти при сворачивании.
- Завершение частично выполненной тренировки, все фактические подходы в истории, исправление результатов с пересчётом статистики, отдельное обновление исходного шаблона после завершения.
- Статистика за неделю, месяц, квартал, год или свой период. Графики с выбором точки и таблицами, разные способы учёта веса отдельно, рекорды без разминки. Основная мышечная группа используется для распределения без удвоения подходов.
- Светлая, тёмная и системная темы; JSON-копия (с пользовательскими изображениями), проверяемый импорт с объединением/заменой, CSV-журнал. Ошибочный импорт не изменяет данные.

## Три персональных шаблона

При первом запуске добавляются однократно:

1. **Спина + грудь + руки** — 7 упражнений.
2. **Ноги + ягодицы — день 1** — 5 упражнений.
3. **Ноги + ягодицы — день 2** — 6 упражнений.

В них 17 уникальных упражнений. Проверка точного состава, порядка и **каждого подхода** находится в `tests/core.test.ts`. Старые демонстрационные шаблоны не добавляются. Ни один шаблон не назначается на день и не считается выполненным без действия пользователя.

| Румынская становая тяга со штангой                         | barbell-rdl          |

- Дробные веса **22,6 / 27,3 / 42,7 / 21,4 кг** хранятся без округления до шага тренажёра. Ввод принимает запятую и точку. Итоговый объём округляется только для отображения до двух знаков.
- В Смите **20 кг — добавленный вес без учёта грифа**, это пояснение есть в карточке настройки веса.
- **6 кг** в сгибаниях и **25 кг** в румынской тяге с гантелями остаются неуточнёнными до выбора способа учёта. Исходные числа автоматически не пересчитываются. Их объём равен нулю до уточнения. «Вес одной из двух гантелей» явно использует ×2, «Общий вес двух гантелей» — ×1. Для движения с одной гантелью используется «Общий вес».
- Отведение ноги содержит **3 отметки левой и 3 правой стороны**, по 10 повторений и 9 кг. Объём всех шести выполненных подходов — **540 кг·повт.**, без повторного удвоения.
- Планка в обоих шаблонах ссылается на одно упражнение: **3 × 45 секунд**, без дополнительного веса, с отдельным таймером подхода.
- Отдых **90 с** — редактируемое значение по умолчанию, не перенос со скриншотов.
- Стабильные ID и маркер `personal-v1` предотвращают повторный посев. Обновления не перезаписывают изменения пользователя.

## Данные и резервные копии

Вся информация находится в IndexedDB `moi-trenirovki`, схема версии 1. Расписание использует локальные календарные даты; фактическое время и таймеры — миллисекунды эпохи. История содержит собственные снимки упражнений и подходов.

Учитываются только отмеченные подходы **завершённых** занятий. Вес помощи и неопределённые веса гантелей не включаются во внешний объём; вес тела не выдумывается. Разминка видна в истории и общей активности, но исключается из силовых рекордов. Разные варианты упражнения и способы учёта веса не склеиваются в один график.

В настройках экспортируйте **JSON** перед очисткой браузера или переносом. Он содержит настройки, каталог, изображения data URL, шаблоны, расписание, исключения, занятия и оба таймера. При объединении совпавшие ID сохраняют текущую запись; импорт второй активной тренировки отклоняется. Для полной замены требуется отдельное подтверждение. Поддерживается JSON версии 1, до 25 МБ; пользовательское изображение — PNG/JPEG/WebP до 2 МБ. CSV — журнал выполненных подходов, не полная резервная копия.

Регулярно сохраняйте копию: браузер может очистить данные при нехватке места. Кнопка защиты хранилища запрашивает persistent storage, но решение остаётся за браузером. Работайте с записью занятия в одной вкладке приложения.

## Проверки

```sh
npm test                 # критическая логика, точность 17 упражнений и трёх шаблонов
npm run build            # строгая проверка TypeScript и production/PWA-сборка
npm run test:e2e          # браузерный основной сценарий и офлайн на 360 px
```

Браузерные проверки используют системный `/usr/bin/chromium` в этой облачной среде. На другой машине установите браузер:

```sh
npx playwright install chromium
CI=1 npm run test:e2e
```

Либо задайте `CHROMIUM_PATH` к своему Chromium. В GitHub Actions браузер устанавливается автоматически. Для `test:e2e` предварительно выполните сборку. Скриншоты и trace при ошибках сохраняются в игнорируемый `test-results/`.

Проверенный основной путь: создание → выбор из нескольких категорий → техника → дробные параметры → еженедельное расписание → календарь → выполнение разных подходов → изменение отдыха и таймер планки → перезагрузка и продолжение → завершение → история и график → изменение шаблона без изменения снимка истории → экспорт и восстановление → отклонение невалидного импорта. Отдельно проверяется загрузка и редактирование офлайн, пять разделов и редактор при ширине 360 px.

## Публикация на GitHub Pages

В репозитории есть `.github/workflows/pages.yml`. Он проверяет логику, сборку и браузерный сценарий; для публикации собирает ресурсы с базовым путём `/<имя-репозитория>/`. Маршруты используют hash, поэтому перезагрузка внутренних страниц не требует настройки серверного fallback. Manifest, иконки и service worker учитывают подпапку.

1. Отправьте изменения в `main` репозитория `avtaiaai-spec/workout`.
2. В GitHub откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Дождитесь успешного workflow **Check and publish to GitHub Pages** (или запустите его вручную в Actions).
4. GitHub покажет адрес опубликованного сайта в Pages и в deployment workflow.

Публикация из этой сессии не выполнялась. Сам факт локальной сборки не означает, что сайт уже опубликован. Для локальной проверки путей production-подпапки:

```sh
VITE_BASE_PATH=/workout/ npm run build
VITE_BASE_PATH=/workout/ npm run preview
```

Для домена без подпапки задайте `VITE_BASE_PATH=/`. Если Pages запрещён политикой организации, потребуется разрешить его в настройках GitHub.

## Установка на iPhone

Откройте **опубликованный HTTPS-сайт в Safari**. Дождитесь загрузки, затем «Поделиться» → «На экран Домой» → «Добавить». Открывайте с полученной иконки. После первой полной загрузки shell приложения и все встроенные схемы кэшируются; конструктор, запись, таймеры, календарь и статистика работают без сети. Пользовательские изображения хранятся в IndexedDB.

Новая версия service worker ожидает закрытия всех окон приложения. Обновление не сбрасывает данные и не перезагружает активное занятие принудительно.

## Ограничения первой версии

- Нет синхронизации между устройствами, аккаунтов, серверной копии и расчёта калорий.
- Иллюстрации — собственные двухмерные схемы, не GIF/видео. Внешних недостающих материалов у встроенного каталога нет. Для собственного упражнения изображение необязательно.
- Звук/вибрация зависят от поддержки браузера и взаимодействия пользователя; фоновые сигналы при заблокированном iPhone не гарантируются.
- Автотесты выполнялись в Chromium на мобильном viewport, а не на физическом iPhone/Safari. Физическое устройство и фактическая публикация требуют отдельной проверки после размещения.
- IndexedDB не является синхронизируемым хранилищем; одновременная запись в нескольких вкладках не поддерживается.

## Структура

`model.ts` — типы, схемы импорта, расчёты и календарь; `catalog.ts` — каталог и версионированный посев; `storage.ts`/`store.tsx` — IndexedDB и очередь записей; `Illustration.tsx` — локальные схемы; `Editor.tsx`, `Catalog.tsx`, `Schedule.tsx`, `Progress.tsx`, `Settings.tsx`, `Timers.tsx` — функции приложения. Секреты и внешние API не нужны.

## Оформление Calm Studio

Все экраны используют общие токены в `src/styles.css`: фон, поверхности, поля, текст, акценты, границы, ошибки, отключённые состояния и палитра схем. Карточки — 20 px, поля и кнопки — 12–16 px; основной текст 16 px, второстепенный не меньше 14 px, основные действия не ниже 48 px. Golos Text с кириллицей поставляется локально и кэшируется для офлайн-работы. Числовые поля, результаты и таймеры используют `tabular-nums`.

В настройках: «Светлая», «Тёмная», «Как на устройстве». По умолчанию — тема устройства. Ручной выбор хранится в прежней IndexedDB; `localStorage` содержит только копию настройки оформления для применения до первой отрисовки React. Недоступность `localStorage` не блокирует сохранение данных. Переходы между темами не изменяют занятия, таймеры, шаблоны и историю. Тема устройства реагирует на её изменение в системе без перезагрузки.

Основные акценты — #087F83 / #61D3CF. Для небольшого текста на мягких поверхностях светлой темы используются #067277 и #5A6F84 вместо более светлых исходных оттенков: контраст текста на всех основных поверхностях не ниже 4,5:1. Границы интерактивных полей имеют контраст не ниже 3:1. Ошибки, графики, календарь, модальные окна и отключённые кнопки используют тематические токены.

Лента недели на главной меняет выбранный день и его планы. В карточках используются реальные количества упражнений (7 / 5 / 6 для исходных шаблонов). Длительность с «~» — только приблизительная оценка (3 с на повторение плюс заданный отдых, без переходов), она не записывается в статистику. Пользовательские изменения состава сразу отражаются в карточках.

Текущий подход выделен. «Записать подход» находится непосредственно под его полями; после записи показывается следующий подход. Миниатюра открывает увеличенную технику. Таймер отдыха находится в отдельной панели в потоке страницы над основным содержимым, с «+15 с» и «Пропустить», и не плавает поверх полей снизу. Заметки и дополнительный учёт веса во время занятия свёрнуты, но доступны. Все прежние функции сохранены, схема данных и исходные 17 упражнений/3 шаблона не менялись.

`tests/design.spec.ts` проверяет семь основных экранов, настройки, технику, заполненные графики, ошибки и ввод результатов при 360 и 1440 px в обеих темах; проверяет контраст токенов, отсутствие переполнения и пересечения подписей навигации. Отдельно проверяются раннее применение сохранённой темы до загрузки React, восстановление выбора после перезагрузки, реакция на тему устройства и неизменность сохранённого занятия, шаблонов, каталога, расписания и таймеров при переключении. Скриншоты доступны в `test-results/calm-*`. Проверка на физическом iPhone по-прежнему не выполнялась.
